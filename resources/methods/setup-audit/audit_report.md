# AI setup audit report — template

This is the canonical shape produced by `ai-setup-inspector`. The real
reports live under `Targets/<target_id>/reports/YYYY-MM-DD_audit.md`
and are generated by `.claude/hooks/ai_setup_inspector.py`. This file
is the human-readable reference: it shows the twelve required fields in
order, so a reader can validate any emitted report against the shape
without reading the Python source.

## Required fields (in order)

1. **Target** — target_id, target_path, vault-relative path, host OS.
2. **Timestamp** — scan started, duration, report version, previous scan.
3. **Scope** — files scanned, AI files, walk exclusions, size cap, symlink policy.
4. **Summary** — maturity, overall footprint, one-liner.
5. **Structural map** — files grouped by category, with relative paths.
6. **Inventory** — per-category count and byte total, table form.
7. **Workflow analysis** — agents, commands, hooks, skills, tests, prompts, registry, surfaces present.
8. **Config quality** — maturity with justification and detected gaps.
9. **Change awareness** — added / modified / removed versus previous manifest.
10. **Recommendations** — concrete next actions.
11. **Risk and fragility** — structural risks detected.
12. **Machine-readable block** — YAML block with the same numbers, for downstream consumers.

## Provenance block

Every report ends with:

- Scanner path (`.claude/hooks/ai_setup_inspector.py`).
- Manifest path (latest + historical).
- Diff path (if applicable).
- Cross-references back to the subsystem README and the three indexes.

## Validation

Any report produced by the inspector must satisfy:

1. Valid frontmatter (passes `pre_commit_gate.py`).
2. All twelve sections present, in order.
3. Machine-readable block parses as YAML and contains at least:
   `target_id`, `target_path`, `scan_started`, `total_files`, `ai_files`,
   `maturity`, `agents`, `commands`, `hooks`, `counts`, `diff`.
4. Cross-references to the subsystem README and the three indexes.
